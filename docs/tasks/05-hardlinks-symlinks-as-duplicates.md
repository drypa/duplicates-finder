# Хардлинки и симлинки ошибочно считаются дубликатами

**Приоритет:** средний
**Файлы:** `cmd/cmd_find.go`, `files/file.go`
**Категория:** ложные срабатывания / удаление

## Проблема

1. **Хардлинки.** Проверка «тот же файл» (`cmd/cmd_find.go:94`) сравнивает только строки

   путей: `sourceFile.FullPath == targetFile.FullPath`. Если source и target — одна и та

   же директория или перекрываются, а два пути являются **хардлинками на один inode**

   (разные пути, одно содержимое), они будут посчитаны дубликатами и могут быть удалены,

   хотя это один и тот же файл.

2. **Симлинки.** `getFilesFromDirIncludeChildren` использует `os.ReadDir` + `entry.IsDir()`

   (по симлинк-директориям не ходит), но **симлинк-файлы** включаются в обход и

   хэшируются по содержимому цели (`os.Stat` в `files.NewFile` следует по симлинку).

   Симлинк, указывающий на файл из source, может быть ошибочно сочтён дубликатом.

## Ожидаемое поведение / решение

1. Для проверки «тот же файл» сравнивать **identity (inode/dev)**, а не только путь —

   например `os.SameFile` между `os.Stat` source и target.
2. Определить политику обработки симлинков (следовать или нет) и явно обрабатывать их,

   если требуется.

## Acceptance criteria

- Хардлинк на один inode не удаляется как дубликат, когда это не является намерением.
- Симлинки обрабатываются в соответствии с задокументированной политикой.
