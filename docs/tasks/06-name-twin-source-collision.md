# Тёзки в source: мапа по имени теряет эталоны

**Приоритет:** средний
**Файлы:** `cmd/cmd_find.go`
**Категория:** ложные отрицательные / недетерминизм

## Проблема

Индекс `sourceFiles` — это `map[string]*files.File`, ключ — только имя файла

(`cmd/cmd_find.go:151`). Если в source в разных поддиректориях лежат **два файла с

одинаковым именем**, в мапе остаётся только **последний обработанный**, а порядок

обработки при параллельном обходе (`getFiles`) **недетерминирован**.

Последствия:

- остальные тёзки теряются — их «дубликаты» в target не находятся (ложные отрицательные);
- для `DeleteSource` удаление эталона недетерминировано: неизвестно, какой именно тёзка

  попадёт в мапу.

## Ожидаемое поведение / решение

1. Решить, как обрабатывать неоднозначность имени: либо хранить список файлов на один

   ключ (`map[string][]*files.File`), либо документировать, что при тёзках поведение

   не определено.
2. Если требуется полная корректность — обходить все тёзки и искать дубликаты среди

   каждого.

## Acceptance criteria

- Поведение при наличии тёзок в source детерминировано и задокументировано.
- Нет ложных пропусков дубликатов из-за перезаписи записи в мапе.
