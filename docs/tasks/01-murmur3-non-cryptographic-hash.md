# Использование некриптографического хэша murmur3 при удалении файлов

**Приоритет:** высокий
**Файлы:** `files/file.go`, `cmd/cmd_find.go`
**Категория:** коллизии / безопасность удаления

## Проблема

При совпадении файлов используется только **murmur3-128** (`files/file.go:39`), который

является **некриптографическим** хэшем. Для злонамеренного сценария подобрать второй файл

с тем же 128-битным хэшем и нужным размером тривиально — атакующий, контролирующий

содержимое, может подменить оригинал.

Приложение **физически удаляет файлы** (actions `DeleteSource`/`DeleteTarget`), поэтому

полагаться только на некриптографический хэш опасно.

Вероятность коллизии murmur3-128 для случайных данных мала, но удаление файлов — операция

необратимая, и дешёвые преднамеренные коллизии делают такой выбор небезопасным.

## Ожидаемое поведение / решение

1. При совпадении размера и хэша выполнить дополнительную **побайтовую проверку**

   содержимого (streaming compare), чтобы подтвердить истинное равенство файлов перед

   любым удалением.
2. В `files` добавить метод сравнения содержимого (например, сравнение по буферу

   обоих файлов), вызываемый из `cmd/cmd_find.go` перед занесением файла в список

   удаления.
3. Опционально: обосновать использование murmur3 в комментарии или заменить на

   криптографический хэш, если побайтовая сверка не нужна по соображениям скорости.

## Acceptance criteria

- Файл попадает в `filesToDelete` только после подтверждения побайтового равенства

  содержимого, а не только по совпадению `Size` + `Hash`.
- Поведение `Print` не изменяется.
