# DeleteSource удаляет эталон вместо дубликата

**Приоритет:** высокий
**Файлы:** `cmd/cmd_find.go`
**Категория:** деструктивность операции

## Проблема

При совпадении файлов для действия `DeleteSource` (`cmd/cmd_find.go:102`) в список

удаления попадает `sourceFile.FullPath` — то есть **эталон**, по которому идёт сравнение,

а не найденный дубликат в target.

Семантически это деструктивно и неожиданно:

- удаляется файл-«оригинал», при этом «дубликат» в target остаётся;
- при нескольких target-дубликатах одного source-файла (одинаковые имена в разных

  подпапках target) эталон добавляется в список удаления несколько раз.

## Принятое решение

**Семантика `DeleteSource` оставлена прежней** — удаляется эталон (source-файл),
совпавший с дубликатом в target, а не сам дубликат. Вариант «удалять дубликаты в target»
был рассмотрен и отклонён.

**Вторая проблема устранена через дедупликацию:** список удаления переведён с массива
на map-сет (`map[string]struct{}`), поэтому один и тот же файл попадает в список
ровно один раз, даже если он совпал с несколькими target-дубликатами.

**Обоснование стоимости:** дедупликация на map не влияет на производительность —
добавление в map амортизированно O(1), итоговая сложность остаётся O(n), а накладные
расходы ничтожны на фоне сканирования и murmur3-хеширования всех файлов.

**Реализация:** `cmd/cmd_find.go`.

## Acceptance criteria

- `DeleteSource` удаляет файлы в соответствии с документированной семантикой
  (удаляет эталон, совпавший с дубликатами в target).
- Один и тот же файл не попадает в `filesToDelete` повторно.
